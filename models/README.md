# Model endpoints

Choose with `--endpoint cao|trapi|vscode|vllm` on a benchmark's `make_specs.py` (default `$DSH_BENCH_ENDPOINT`, else
`cao`), or name a model file with `--model`. How to bring each endpoint up: [endpoints/README.md](../endpoints/README.md).

| File | Endpoint | Model and settings |
|---|---|---|
| `luna-cao.json` | `cao` (default) | GPT-5.6 Luna on CAO directly (`127.0.0.1:4141/v1`, Responses API): the AHE campaign 34 request shape (reasoning summaries on, encrypted reasoning sent back each turn, 128K output cap, no temperature) at effort **high** (user's choice, 2026-11-06; c34 itself used the provider default, medium). Every tool goes with an explicit `strict: false` (`supportsStrictMode: true`) and a request is retried on `INVALID_REQUEST` too (2026-11-09): with `strict` left out, OpenAI sometimes compiled tool schemas strictly mid-run and refused a `oneOf` schema with a 400 that ended the run (11% of APEX-Agents 1.1 runs). |
| `luna-max-cao.json` | (`--model`) | Same as `luna-cao` at effort **max** (CAO lists none/low/medium/high/xhigh/max for gpt-5.6-luna; checked 2026-11-08 that DSH sends `reasoning.effort: max`). `supportsStrictMode: true`, so every tool goes with an explicit `strict: false` (omitted, OpenAI sometimes compiled tool schemas strictly and refused a `oneOf` schema with a 400, ending 11% of runs; 2026-11-09), and the request is retried on `INVALID_REQUEST` as well (5 retries). |
| `sol-high-cao.json` | (`--model`) | GPT-5.6 Sol (`gpt-5.6-sol`) on CAO, otherwise exactly `luna-cao`'s shape: Responses API, effort high, reasoning summaries requested with encrypted reasoning sent back, 128K output, `strict: false` and the same retries. First used for Harvey FK-250 (2026-11-10). |
| `gemini-argon-high-cao.json` | (`--model`) | Gemini 4 Argon (`gemini-4-argon`) on CAO, Chat Completions (the only API CAO offers for Gemini), `reasoning_effort: high` = the highest CAO lists (low/medium/high; checked 2026-11-10), 983,040 prompt tokens, 65,536 output. Explicit compat: no `store`, system role (not developer), `max_tokens`, no `strict` on tools. Copilot returns `reasoning_text` (kept as reasoning) and an encrypted `reasoning_opaque`, which pi-ai does not send back; a two-turn tool call works without it (checked 2026-11-10), but unlike the Luna files the model does not get its earlier reasoning back. Same retries as `luna-cao`. |
| `opus55-max-cao.json` | (`--model`) | Claude Opus 5.5 (`claude-opus-5-5`) on CAO through its Anthropic Messages API (`127.0.0.1:4141`, `/v1/messages`), effort **max** (CAO lists low/medium/high/xhigh/max; Opus 5.5's own default is medium), adaptive thinking with summaries (`forceAdaptiveThinking`; Opus 5.5 rejects `budget_tokens` and disabled thinking), thinking blocks sent back with their signatures each turn, 1M context, 128K output, no temperature. Checked 2026-11-10: two-turn parallel tool call with replayed thinking at effort max works through CAO, with `x-api-key` auth. Same retries as `luna-cao` plus `PI_AI_ERROR` (2026-11-10: CAO ended both first runs with a mid-stream Anthropic `api_error` "An unexpected error occurred during streaming, retry your request.", which DSH classifies as `PI_AI_ERROR`, not retried by default). |
| `luna-trapi.json` | `trapi` | GPT-5.6 Luna deployment `gpt-5.6-luna_2026-07-09` through the TRAPI token proxy (`127.0.0.1:8031/v1`), same request shape and effort as `luna-cao`. Context 262,144 (TRAPI's limit for the deployment is not recorded here). Every tool goes with an explicit `strict: false` (`supportsStrictMode: true`) and a request is retried on `INVALID_REQUEST` too (2026-11-09): with `strict` left out, OpenAI sometimes compiled tool schemas strictly mid-run and refused a `oneOf` schema with a 400 that ended the run (11% of APEX-Agents 1.1 runs). |
| `luna-vscode.json` | `vscode` | GPT-5.6 Luna through the GH Copilot Server VS Code extension, via the streaming shim (`127.0.0.1:8032/v1`), Chat Completions. The extension drops reasoning, reports zero usage, and turns system messages into user messages. |
| `qwen38-vllm.json` | `vllm` | Qwen3.8-27B (FP8 checkpoint, served as `Qwen/Qwen3.8-27B-FP8`) on local vLLM (`127.0.0.1:8000/v1`), agentic-evolution's JobBench Qwen3.8 route: thinking on (chat-template kwargs), 262,144 context, 32,768 output cap, a response cut at the cap regenerated up to 3 times (`dsh_rows`: agent-loop `maxTokensRetries`). |
| `luna-proxy-high.json` | (record) | The JobBench parity run of 2026-11-05: Luna through agentic-evolution's model_serve proxy on :8018, effort high, 262K context, 32K output. |

The local endpoints (trapi, vscode, vllm) share one token, `~/.config/dsh-bench/endpoint.token` (mode 600, created on
first use): DSH sends it, the proxy or vLLM checks it, and no real key reaches DSH.
